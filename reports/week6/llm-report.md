## Human contribution and decisions

The team remained responsible for:

- selecting the actual Sprint 4 scope;
- creating GitHub issues, milestone, Project view, branches, and PRs;
- checking whether the drafted text matches the actual repository state;
- replacing TODO placeholders with real evidence;
- collecting real customer feedback;
- creating the real Week 6 release;
- verifying links, screenshots, and Moodle submission evidence.

LLM output was not treated as automatic evidence. Any statement about customer feedback, UAT results, release status, product access, or transition readiness must be supported by actual team work and repository evidence.

## Limitations of LLM use

LLM-generated drafts may contain placeholders or assumptions. The team must review and update them before submission.

The following items must not be invented by an LLM:

- customer feedback;
- UAT results;
- release links;
- product access links;
- private recording links;
- exact timecodes;
- customer acceptance or transition confirmation;
- final MVP v3 status.

## Public/private evidence handling

LLM support was also used to keep the public report sanitized.

The public repository must not include:

- private credentials;
- private customer-identifying evidence;
- private recording links;
- exact private timecodes;
- private consent evidence;
- restricted access instructions;
- Moodle-only evidence.

Private evidence is provided only through the Week 6 Moodle PDF submission when required.
