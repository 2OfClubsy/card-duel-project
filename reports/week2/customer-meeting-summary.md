# Customer Meeting Summary

## Date

11 June

## Participants

* Customer
* Team members
* Moderator
* Note-taker

## Artifacts demonstrated

During the meeting, the team presented the following artifacts:

* User stories
* MoSCoW priorities
* Initial proposed MVP v1 scope
* Miro prototype
* Game concept
* Game loop

## Discussion points

The team presented the current product idea: a horror-inspired card duel game with risk-based decisions and opponent interaction.

The customer reviewed the proposed user stories, their MoSCoW priorities, and the initial MVP v1 scope. The team also demonstrated the Miro prototype, explained the main game concept, and showed the planned game loop.

The main discussion focused on whether the selected user stories match the intended product direction and whether the planned visual format supports the atmosphere of the game.

## Decisions

The customer approved the documented user stories, MoSCoW priorities, and initial proposed MVP v1 scope.

The customer suggested changing one of the user stories because a separate demo version is not very relevant for the current course project scope.

The customer also recommended making the game mostly in 3D, because a 2D format would not provide enough immersion and atmosphere for this type of horror-inspired game.

## Action points

* Replace the user story about the demo version with a more relevant story.
* Keep the same priority for the updated story.
* Continue developing the game as a mostly 3D product.
* Use small 2D elements only where they are appropriate, such as UI, card display, or interface overlays.
* Update the user stories and project documentation according to the customer feedback.

## Risks

* A fully 3D game may require more development time than a 2D prototype.
* The team needs to keep the MVP v1 scope small to avoid making the project too complex.
* The horror atmosphere depends on visual style, sound, and presentation, so the team should avoid spending too much time on non-essential content before the core gameplay loop works.

## Feedback

The customer gave two main pieces of feedback:

1. The user story about a demo version should be changed because a separate demo version is not very suitable for the current product scope.
2. The game should be developed mainly in 3D, because immersion and atmosphere are important for this type of game.

## Customer approvals

The customer approved:

* The documented user stories
* The MoSCoW priorities
* The initial proposed MVP v1 scope

The customer also confirmed that the team can continue with the proposed product direction after applying the discussed changes.

## Resulting changes

The team decided to replace the previous US-06 with a new story focused on 3D immersion and atmosphere.

The team also decided to make the game mainly in 3D, while still using 2D elements where they are useful for cards, UI, menus, and visual clarity.
