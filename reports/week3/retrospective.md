# Week 3 Sprint Retrospective

## What went well

1. **The team successfully organized the Product Backlog and Sprint Backlog in GitHub.**
   The team migrated the user stories and supporting PBIs into GitHub Issues, added labels, assigned them to the Sprint milestone, and organized them through GitHub Project views. This made the MVP v1 scope easier to inspect and verify.

2. **The team improved traceability between issues, pull requests, reviews, and evidence.**
   Week 3 work was connected to GitHub Issues and reviewed pull requests. This helped the team show who worked on each item, who reviewed it, and how each change supported Assignment 3 requirements.

3. **The customer review confirmed the current direction.**
   The customer approved the Product Backlog, Sprint Backlog, MVP v1 Scope, user stories, and acceptance criteria. This gave the team confidence that the current 3D card-duel direction and MVP v1 scope were appropriate.

## What did not go well

1. **Some documentation and evidence were prepared later than expected.**
   Several required files, links, screenshots, and report sections had to be added near the end of the assignment. This created extra pressure during the final submission stage.

2. **GitHub workflow setup took more time than expected.**
   Issue templates, labels, milestones, project views, pull request templates, changelog updates, release evidence, and link checks required careful setup and repeated verification.

3. **Some links and access settings needed additional checks.**
   GitHub Project links, Google Drive access, and Markdown links had to be tested carefully to make sure they were accessible to external reviewers and did not fail automated link checking.

## Action points

1. **Prepare the report structure earlier in the next Sprint.**
   The team should create required report files at the beginning of the Sprint and update them gradually instead of completing most documentation at the end.

2. **Use a final evidence checklist before submission.**
   The team should maintain a checklist for required links, screenshots, releases, customer review evidence, PR reviews, and access permissions. This will reduce the risk of missing required artifacts in future assignments.
